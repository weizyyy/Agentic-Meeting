# 数据治理

[English](../data-governance.md) · **简体中文**

## 1. 存储内容

`session.data_dir`（默认 `data`）存放应用数据。标准麦克风链路在内存中处理音频以进行识别和说话人区分，不归档原始麦克风录音。「正在转录」表示转录，不表示生成音频录制文件。

| 数据                                                 | 位置                                              |
| ---------------------------------------------------- | ------------------------------------------------- |
| 会议标题、说话人、连接历史、发言、全文索引与发言向量 | `<data_dir>/meetings.db`                          |
| 截图时间、描述和文件引用                             | 数据库；图片在 `<data_dir>/sessions/<id>/frames/` |
| 运行摘要（digests）和会后报告                        | 数据库                                            |
| 任务目标、结果、来源、进度事件与外发元数据           | 数据库                                            |
| 持久任务输入副本与取回的产物                         | `<data_dir>/sessions/<id>/tasks/<label>/`         |
| 服务/应用日志                                        | `<data_dir>/logs/`                                |

沙箱工作区独立存在：Docker 每任务一个容器（默认工作区 `/workspace`），local SDK 使用临时目录，不把宿主任务目录挂载为工作区。运行器复制输入到沙箱，仅将报告中指定的产物取回持久任务目录。退出任务上下文时尝试关闭并删除沙箱，清理失败会记日志。这些临时工作区不是保留清理扫描根，因此删除任务目录不保证清除失败或崩溃遗留的沙箱副本。

下载导出是独立副本，保存在操作者/浏览器选择的位置。日志和任务结果也可能含会议内容，不能视为发言表的同一份数据。配置、环境密钥、模型、运行时文件和证书不在保留清理范围内。

## 2. 数据流向

浏览器把麦克风音频和共享截图发送给配置的会议服务器。随网页打包的 `WavMediaManager` 在本机采集麦克风，不下载 Daily 的 call-machine 脚本或使用其错误上报服务。这不取消配置的推理目的地或 STUN/TURN 连接。切换麦克风会替换连接中的音频发送轨道，不改变保留策略或转录指示。

推理是否留在该服务器，取决于**各个实际服务地址**，不能仅看模式名称叫 local 或是否启用进程启动。同一局域网的另一台机器也属于离开会议服务器的目的地。开会前核对：

| 配置/功能                                     | 配置目的地接收的数据                                                                                        |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `asr.base_url`                                | 音频窗口与识别提示/上下文；识别与分词都调用 ASR 服务                                                        |
| `embedding.base_url`                          | 发言文本与语义召回查询                                                                                      |
| `tts.base_url`（启用时）                      | 待播放文本，可能包括会议内容及助理/任务结果                                                                 |
| 生效的 `realtime_llm` 地址                    | 会议上下文：转录、摘要、助理/工具往来；支持并使用视觉时包括图片                                             |
| `screen.caption_provider`                     | 截图发往选定的实时或后台模型生成描述                                                                        |
| `realtime.digest_provider`；`report.provider` | 转录/上下文交给选定的实时或后台模型；启用后台截图附带与视觉时包括选取的截图输入                             |
| `agent.base_url`                              | 委托目标、选取的转录、任务/工具往来；启用 `agent.attach_frames` 和 `agent.supports_vision` 时包括选取的截图 |
| `agent.mcp_servers`                           | 按实际调用工具发送参数/结果                                                                                 |
| `agent.sandbox`                               | 任务代码与输入，包括复制的截图文件；`network` 单独控制网络访问                                              |

说话人区分使用配置的进程内原生后端。`check`/`serve` 和浏览器会提示部分配置外发情形，但不是完整的目的地审计。服务提供方、工具和允许联网的沙箱代码可能保留自己的副本。应用保留期限与人工删除不能撤回已外发的数据。

## 3. 保留期限与保留标记

`[retention]` 的四类期限默认均为 `0`：原有数据无限期保留。仅启用确实要清理的类别；零表示关闭，不是立即过期。期限为 0–36500 的严格整数。`cleanup_interval_secs` 默认为 3600，范围 60–86400。

一天为 86400 秒。每轮只采样一次服务器 UTC Unix 时间，仅清理锚点**严格早于** `now - days * 86400` 的数据；等于截止点或在未来的时间仍保留。

| 期限                  | 时间锚点                                                 | 删除内容                                          |
| --------------------- | -------------------------------------------------------- | ------------------------------------------------- |
| `transcript_days`     | 会议不活跃时间：开始、最后活跃、结束时间（若有）的最大值 | 发言、对应向量与全文索引                          |
| `screenshots_days`    | 同一会议不活跃锚点                                       | 截图记录（含描述）与自有 `frames/` 子树           |
| `reports_days`        | 各终态报告的完成时间；各运行摘要的创建时间               | 终态报告与摘要记录                                |
| `task_artifacts_days` | 各终态任务的完成时间；旧终态任务缺失时采用创建时间       | 自有任务目录与 `artifacts_json` 清单（置为 `[]`） |

中断但未结束的会议也可能过期。正在进行或有受保护后台工作的会议会跳过，包括排队/运行任务以及尚未结束的写入/收尾。新报告和任务文件的时钟开始更晚，因此可能比原会议保留更久。

在会议列表或详情点「保留」，让该会议免于四类自动清理。标记持久保存，重启后仍在，只有服务器请求成功后界面才更新；失败会显示错误。会议进行中也能修改。保留不能恢复已移除文件；已有清理占用时可能返回冲突，稍后重试。人工删除忽略保留标记。

自动清理仍保留会议元数据（标题、说话人、连接历史、保留标记）、任务目标/结果/来源/事件/外发元数据、日志和导出文件。任务目录清理后，目标、结果或事件中仍可能留有输入原文副本。转录过期不会擦除截图描述、摘要、报告或任务文本：它们是独立副本，采用各自期限或保留到整场会议删除。

## 4. 完整删除与恢复边界

会议列表的人工删除明确移除整场会议，包括已保留的会议。正在进行或受保护工作忙时返回 409，不开始删除。获准后先持久标记「待删除」，再清理自有文件、向量和数据库记录（包括关联任务/事件、报告、摘要、截图、说话人与连接）。

待删除会议仍能读元数据，但内容/导出、改名、保留、继续、结束与新工作被禁止。页面显示「待删除」，列表保留「重试删除」。保留不能撤销此状态。真实文件/数据库失败返回 500，部分文件可能已移除；页面刷新列表/详情，不宣称成功。修复服务器问题后重试 DELETE；后续轮次与重启也会重试，即使所有类别清理关闭。只有完成删除才返回成功；已完全移除的 id 再次删除返回 404。

清理仅删除验证过的应用自有子路径，拒绝不安全链接/路径逃逸。修复权限、磁盘错误或被拒绝的路径归属，不要换路径强行重试。文件移除与数据库提交不是一笔原子事务。没有撤销功能，也不保证安全擦除：SQLite 页/WAL、存储快照、备份、导出下载、外部服务及日志中仍可能有副本。保留清理不会压缩或消毒这些副本。操作者需单独管理备份/导出/日志期限；恢复备份可能恢复已删除内容及旧保留标记。

配置见[配置说明](configuration.md#retention)，错误见[故障排查](troubleshooting.md#保留清理与待删除)，精确契约见[接口 §8.4](interfaces.md#84-保留清理与完整删除)。
