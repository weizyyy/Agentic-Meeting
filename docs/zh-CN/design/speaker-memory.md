# 设计：跨会议记住说话人

[English](../../design/speaker-memory.md) · **简体中文**

状态：**提案**，对应 [#25](https://github.com/weizyyy/Agentic-Meeting/issues/25)。本文内容尚未实现。
各部分落地时，接口移入 [interfaces.md](../interfaces.md)、[configuration.md](../configuration.md) 和
[data-governance.md](../data-governance.md)，本文只保留设计理由。

## 1. 目标

现在每场会议的说话人都重新编号（「说话人 1」「说话人 2」……），主持人每次都要改名。做了这个功能后，
服务端能认出以前教过的声音，为说话人**建议**一个名字，由主持人确认或忽略。任何改名都不会悄悄发生。

issue 提出的要求：

- 另外引入声纹（说话人嵌入）模型（§2），这是一个新的运行时依赖（§3）。
- 从已有会议录入（「这位说话人是……」）并保存声纹档案（§6）。
- 会议开始后尽早比对，有置信度门槛，以建议的形式交主持人确认（§7）。
- 声纹档案属于生物特征数据：自愿开启、可按人删除、受 [#11](https://github.com/weizyyy/Agentic-Meeting/issues/11)
  的保留期规则约束、绝不发往远程服务（§8）。
- 不配置模型就不开启，不会自动下载任何东西（§10）。

不在范围内：识别从未录入过的人；用声音以外的方式识别身份；改动流式说话人区分本身。

## 2. 为什么只靠说话人区分不够

说话人区分后端（NeMo-Speech.cpp v0.2.0 上的流式 Sortformer 模型，见
[interfaces.md §4.2](../interfaces.md)）按**出现顺序分配槽位**：槽位 1 就是这条流里第一个开口的人。
槽位号在会议之间不代表任何身份，模型能区分的槽位数也很少且固定（目前测试过的模型是四个）。
它内部的说话人缓存存的是编码器帧，不是为声纹验证训练的向量，C 接口也只给出分段
（`start_time`、`end_time`、`speaker`）。锁定版本的 NeMo-Speech.cpp 没有声纹模型或接口。

所以需要第二个模型：**声纹**（说话人验证）模型，把一个人几秒钟的语音变成定长向量，同一个人的向量
余弦相似度高、不同人的低，且与会议无关。

提议：以精确版本号把 `sherpa-onnx` 加为新的可选依赖组 `speaker`（`uv sync --extra speaker`），并装进应用容器

## 4. 总览

```text
麦克风音频 ──► 记录器 ──► 说话人区分（槽位） ──┐
     │                                        │ 已稳定的单人片段
     └──► 30 秒环形缓冲 ─────────────────────► 切片器 ──► 声纹服务 ──► 片段向量
                                                         （仅 127.0.0.1）   │
字幕（主持人修正后的 speaker_idx） ─────────────────────────────────────────┤
                                                                            ▼
                                     每位说话人在本场的声纹 ──► 与声纹档案比对
                                                                            │
                                     主持人：确认 / 忽略 ◄── 建议 ◄─────────┘
                                     主持人：「记住这个声音」 ──► 声纹档案（含本人同意）
```

## 5. 声纹片段

**声纹服务。** 一个小进程 `agentic-meeting speaker-service` 封装提取器，和其他推理服务一样受进程监管
（`launch.*`、健康检查、退避重启）。它接收 16 kHz 单声道 PCM，返回一个 L2 归一化的向量。放在进程外，
原生代码崩溃或计算耗时都不会影响事件循环和转录（硬规则 7），端到端测试也能在 `tests/e2e/inference.py`
里用假服务替换它。它的地址必须是回环地址，配置校验拒绝其他地址（§8）。

**切片。** 记录器本来就按顺序把全部音频送给说话人区分。另设一个环形缓冲，保留最近 30 秒（约 1 MB）。
每 2 秒：

1. 取到 `labeled_secs − 2 秒` 为止的说话人分段；流式模型还会修订最近几秒。
2. 只保留恰好一个槽位在说话的部分：去掉与其他槽位重叠的部分，以及助理说话的时段（回声窗口同
   [interfaces.md §4.3](../interfaces.md)）。
3. 两端各裁掉 0.2 秒，切成不超过 6 秒的窗口，保留不短于 1.5 秒的窗口。
4. 把每个窗口送给声纹服务（超时 5 秒，有界队列；队列满时丢弃最旧的窗口）。

没有说话人区分时（`diarization.backend = "none"` 或已降级），改按字幕的时间范围切窗口。这样主持人手动
分配的说话人仍然可以录入。

**存储。** 每个向量作为本场会议的一个声纹片段保存，带时间范围和槽位。片段本身不记说话人：它的说话人是
覆盖它一半以上时长的那条 ASR 字幕的 `speaker_idx`，在使用时读取。因此重新分配字幕、合并说话人和延迟
校正都会让片段随文字一起移动，主持人的修正就是真值。没有被任何字幕覆盖的片段（咳嗽、噪声）被忽略。

**某位说话人在本场的声纹**是其片段按时长加权的均值再归一化；其**有效语音**是这些片段的总时长。

## 6. 声纹档案与录入

声纹档案是一个有名字的人，最多带八个**样本**；一个样本是此人在某一场会议里的声纹。档案在整个部署
（一个数据目录）内共享，不属于某一场会议。

**录入**是主持人对进行中或已结束会议里某位说话人的显式操作：「记住这个声音……」，填写名字（预填说话人的
显示名，并提供 `session.members` 作为选项），并必须确认本人已同意。需要至少 `min_enroll_secs` 的有效语音，
不足时页面说明还差多少。录入到已有档案时会增加一个样本。录入后该说话人与档案关联。

**更新。** 主持人确认建议后，说话人与档案关联。`auto_update` 开启时，会议结束后把这场的声纹作为样本加入
档案，替换同一场会议的旧样本；保留最近八场。这样档案能适应不同麦克风和房间，而不必再问一次。

**模型变化。** 每个档案记录模型文件的指纹（SHA-256 和向量维度）。来自其他模型的档案不参与比对，页面显示
为需要重新录入；不会在模型之间转换向量。

## 7. 比对与建议

本场会议里编号为正、尚未关联档案的每位说话人，有效语音达到 `min_match_secs` 时比对一次，之后随语音增加
最多每 5 秒比对一次：

1. 每个兼容档案的分数，是说话人声纹与该档案各样本余弦相似度的最大值。
2. 最佳档案的分数不低于 `match_threshold`，并且比第二名至少高出 `match_margin` 时，提出建议。
3. 按分数贪心分配，一个档案最多建议给一位说话人；跳过本场已关联的档案和主持人忽略过的组合。

主持人页面在说话人旁边显示建议（「可能是 张三」）。**确认**把说话人改名为档案的名字（与手动改名相同的
广播）并建立关联；**忽略**在本场记住这个组合。之后的比对不再支持某条未处理的建议时，撤回它。已结束的会议
可以按需从保存的片段计算建议，所以录入之后也能给以前的会议补上名字。

写进使用指南的局限：说话人区分模型能分的槽位很少，一个槽位混了两个人时比对效果差；零星插话的语音不够
比对；声音相近的人可能被认错，所以不经确认不会应用任何建议。

## 8. 隐私规则

声纹片段和声纹档案都属于生物特征数据。

- **默认关闭。** `speaker_memory.backend = "none"` 时不计算任何声纹、不保存片段，也没有相关接口和消息。
- **按人自愿。** 比对只使用经显式录入并确认本人同意的档案。功能开启期间会为每个说话的人计算片段，以便
  之后从以前的会议录入；`store_session_voice = false` 时片段只在进行中的会议内存里保留。录音提示会说明
  正在处理声纹特征。
- **可按人删除。** 删除一个档案会删除它的样本，以及所有会议里归属于关联说话人的片段。清除某场会议的声纹
  数据会删除这场的片段并保留文字记录。两者在页面和命令行里都能操作。
- **保留期。** 片段属于 [interfaces.md §8.4](../interfaces.md) 的文字记录类别：随它过期，完全删除会议时一并
  删除。档案有自己的期限 `retention.voice_profiles_days`，从最后一次更新或确认匹配算起；样本是副本，在此
  之前不随来源会议的删除而消失。
- **绝不外发。** 声纹服务必须监听回环地址；向量和分数不出现在 HTTP 响应、导出、LLM 上下文、工具结果、任务
  输入和日志里。档案名字只有在主持人确认、成为说话人显示名之后才会进入 LLM，与手动改名完全相同。

## 9. 访问控制与身份

按会议的访问控制和本地账号（[#22](https://github.com/weizyyy/Agentic-Meeting/issues/22)）在另一条线上确定，
本功能以那里最终合入的身份模型为准。

- 在目前的共享访问口令下，登录后的人都可以做所有操作，与现在改说话人名字相同。
- 有了按会议的角色后，录入、确认、忽略、清除某场会议的声纹数据需要这场会议的主持人角色。查看、改名和删除
  档案对已登录的本地账号开放，对通过分享链接或会议口令进入的访客不开放。档案可以关联到一个本地账号，
  方便本人找到并删除自己的档案。
- 建议只发给主持人页面，不进入旁观设备的事件流。

多场会议同时进行时（[#23](https://github.com/weizyyy/Agentic-Meeting/issues/23)）共用一个声纹服务，每场会议
有自己的片段队列，轮流处理。

## 10. 要增加的接口

这些先写进参考文档，再写代码（硬规则 9）。名称均为提议。

**配置** `[speaker_memory]`：

| 键                    | 默认值                    | 含义                                                        |
| --------------------- | ------------------------- | ----------------------------------------------------------- |
| `backend`             | `"none"`                  | `"none"` 或 `"sherpa_onnx"`                                 |
| `base_url`            | `"http://127.0.0.1:8084"` | 声纹服务；只允许回环地址                                    |
| `min_match_secs`      | `10`                      | 开始比对前需要的有效语音                                    |
| `min_enroll_secs`     | `20`                      | 录入需要的有效语音                                          |
| `match_threshold`     | 标定后确定（§3）          | 提出建议的最低余弦相似度                                    |
| `match_margin`        | `0.08`                    | 需要领先第二名的幅度                                        |
| `auto_update`         | `true`                    | 确认过的会议作为样本加入档案                                |
| `store_session_voice` | `true`                    | 片段随会议保存；`false` 只在进行中的会议里保留              |
| `launch.*`            |                           | `enabled`、`model_path`、`num_threads`、`env`、`extra_args` |

`[retention] voice_profiles_days`，默认 `0`（删除前一直保留）。

**数据库**（增量迁移）：`voice_clips`（会议、时间范围、槽位、时长、向量、写入令牌；随会议级联删除）、
`voice_profiles`（名字、可选的账号、时间戳、模型指纹）、`voice_profile_samples`（档案、来源会议——该会议
删除后置空、时长、向量）、`speakers.voice_profile_id`，以及每场会议被忽略的组合。

**HTTP：** `GET /api/voice-profiles`、`PATCH`/`DELETE /api/voice-profiles/{id}`、
`POST`/`DELETE /api/speakers/{idx}/voice-profile`（录入或关联、取消关联）、`GET /api/speaker-suggestions`、
`POST /api/speaker-suggestions/accept` 和 `/dismiss`、`DELETE /api/sessions/{id}/voice`。响应只含名字、时长、
日期和取整后的分数，从不包含向量。

**数据通道：** `speaker_suggestion` 和 `speaker_suggestion_cleared`，只发给主持人页面。

**命令行：** 运维用的 `agentic-meeting voice-profiles list | delete <id>`，在服务停止时使用。

## 11. 故障处理

声纹服务和嵌入服务一样是可选的。未配置、启动失败、超时或返回错误时，片段窗口被丢弃，比对暂停，每次
故障在页面上提示一次；字幕、说话人区分和存储照常进行。模型指纹与已存档案不一致时，`check` 和 `serve`
给出警告，不阻止启动。

## 12. 测试

`tests/e2e/` 里的端到端场景，使用对每段录音返回固定向量的假声纹服务，字幕由手动分配给说话人（测试环境
里说话人区分是关闭的）：

- 在一场会议里录入说话人，在第二场播放同一段录音，收到建议，确认后看到改名；在第三场忽略它；
- 有效语音不足 `min_enroll_secs` 时拒绝录入；功能关闭时没有任何相关接口、片段和消息；
- 删除档案会删除其样本和关联片段；清除一场会议的声纹会保留字幕；文字记录和档案的保留期删除应删的内容；
- 声纹服务失败或变慢不会拖慢字幕。

`tests/test_real_services.py` 里加一个 `@pytest.mark.gpu` 用例，在用户的机器上用真实模型和真实说话人区分运行。
