# Meeting access and ordered event recovery

With `server.meeting_access=true`, the single `/api/sessions/{id}/events` route and `WatcherHub` retain the ordered epoch/sequence protocol, snapshots, bounded replay, reset, and slow-send deadline. Every subscription belongs to one immutable authenticated login and meeting. A cursor is recovery position, never authority: authorize before subscribing, before snapshot/replay delivery, and before every outbound chunk. Another meeting's cursor can only trigger an authorized reset/snapshot of the requested meeting.

Membership removal, logout (one login or all), and login expiry close every affected open stream within one second, even while idle or blocked sending; discard its queued events and release its watcher. A later login must create a newly authorized subscription. Other users and meetings remain subscribed. Downloads and late HTTP results keep the same current-authorization checks. Browser revocation clears the view and materials, closes the subscription, invalidates outstanding request generations, and discards the old event cursor; it must not render an earlier replay/snapshot after access is lost.

All-meeting ASR/LLM/TTS health notices remain meeting events; typed-input validation and queue notices remain requester-only. R02 interrupted/live recovery stays intact. Only the exact current recording login can use the tool pipeline; other authorized hosts and question-enabled watchers use bounded tool-free questions. Host HTTP management, immutable source meeting/login for delayed tool callbacks, CSRF, local identities, and legacy mode remain the S04 contracts. No second event hub, alternate event route, or mutable current actor is introduced.

Acceptance uses the real app and fake HTTP inference: two meetings and identities; foreign and stale cursors; snapshot/replay reset with no unauthorized material; two simultaneous streams revoked/logout/expired; a newly logged-in ungranted viewer cannot inherit the old cursor; and a blocked sender must release without affecting another meeting. Existing S04 artifact/RTC/late-tool/budget and R02 ordering/recovery/requester-notice scenarios remain required. This document defines integration scope, not acceptance or publication approval.

Revocation releases the server request and subscription, not historical bytes already delivered to a client or queued in TCP. A blocked final response is cancelled within a further 0.5 seconds and leaves a visible timeout; it does not delay the existing 15-second general send bound.
